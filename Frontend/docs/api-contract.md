# Контракт подбора Tandau

Frontend не требует создания запроса отдельным вызовом: **один POST → один JSON-ответ**. URL задаётся через `VITE_RECOMMENDATIONS_URL`. Backend может внутри выполнять несколько шагов и хранить запросы, но интерфейсу нужен один endpoint.

## Запрос

```http
POST /api/recommendations
Content-Type: application/json
Accept: application/json
```

```json
{
  "city": "Алматы",
  "event_date": "2026-10-10",
  "event_format": "корпоратив",
  "category": "Ведущий",
  "budget_kzt": 1000000,
  "duration_hours": 6,
  "language": "русский",
  "preferences": "Спокойная подача, интеллигентный юмор"
}
```

Все восемь ключей передаются всегда. Неуказанные `duration_hours` и `language` равны `null`, пожелания — пустой строке. Бюджет — целое число тенге, без пробелов и знака валюты; длительность — число; дата — `YYYY-MM-DD` без времени и часового пояса. Бюджет от 1 до 1 000 000 000, длительность больше 0 и до 24 часов, пожелания до 500 символов. Поддерживаемые значения справочников находятся в `request.schema.json`.

Пока действует окно календаря 23.09–31.12.2026. Это ограничение нужно обновить одновременно на frontend и backend при расширении каталога.

## Ответ

Ответ HTTP 200 содержит:

| Поле              | Содержание                                                                |
| ----------------- | ------------------------------------------------------------------------- |
| `status`          | `MATCHED`, `CATEGORY_ABSENT` или `NO_MATCH`                               |
| `request`         | Точные нормализованные параметры полученного запроса                      |
| `catalog_count`   | Число профилей в выбранных городе и категории до строгой фильтрации       |
| `eligible_count`  | Число профилей после всех строгих фильтров, до ограничения в три карточки |
| `recommendations` | От нуля до трёх карточек, уже в итоговом порядке                          |
| `exclusions`      | Сводка исключений без повторного учёта одного профиля                     |
| `alternatives`    | Вычисленные изменения условий; пустой массив, если их нет                 |
| `catalog_version` | Версия каталога и календарей                                              |
| `ranking_version` | Версия правил ранжирования                                                |

Минимальный полный пример пустой выдачи:

```json
{
  "status": "CATEGORY_ABSENT",
  "request": {
    "city": "Астана",
    "event_date": "2026-10-10",
    "event_format": "свадьба",
    "category": "Декоратор",
    "budget_kzt": 3000000,
    "duration_hours": null,
    "language": null,
    "preferences": ""
  },
  "catalog_count": 0,
  "eligible_count": 0,
  "recommendations": [],
  "exclusions": [],
  "alternatives": [],
  "catalog_version": "hackathon-66-v1",
  "ranking_version": "your-ranking-v1"
}
```

### Карточка

Каждый элемент `recommendations` содержит:

- `contractor` — полный профиль, чтобы UC-13 работал без отдельного GET.
- `explanation` — конкретные 1–2 предложения, подтверждённые данными.
- `available_on` — выбранная дата, подтверждённая календарём.
- `matched_preferences` — массив совпавших особенностей; при отсутствии совпадений `[]`.
- `evidence` — непустой массив `{ "label": "Дата", "value": "10 октября — нет занятой даты", "source": "Календарь профиля" }`.

Профиль `contractor`:

| Поле                                      | Тип и назначение                                                                                             |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `id`, `name`                              | Стабильный ID и отображаемое имя                                                                             |
| `category`                                | Категория текущего запроса                                                                                   |
| `categories`                              | Все категории профиля, массив строк                                                                          |
| `city`                                    | Город из справочника                                                                                         |
| `price_from_kzt`                          | Неотрицательная стартовая цена, число                                                                        |
| `event_formats`, `languages`              | Поддерживаемые форматы и языки                                                                               |
| `max_hours`                               | Положительное число или `null`, если неприменимо                                                             |
| `description`                             | Полный исходный текст профиля                                                                                |
| `specialty`                               | Короткая подтверждённая особенность для подзаголовка                                                         |
| `features`                                | Массив `{ "label": "Интеллигентный юмор", "quote": "точная выдержка", "keywords": ["юмор"] }`; допустим `[]` |
| `origin`                                  | `catalog`, `synthetic` или `demo`                                                                            |
| `price_is_estimated`, `city_is_estimated` | Исходные признаки дополнения данных, boolean                                                                 |
| `artwork`                                 | Оформление иллюстрации: `sage`, `clay`, `blue`, `rose`, `sand`, `forest`                                     |

Иллюстрации не являются фотографиями. Backend может выбирать стабильный `artwork` по ID; это не влияет на ранжирование. Поля `features` и `matched_preferences` оставлены для дальнейшего смыслового ранжирования и проверки оснований; frontend не пересортировывает ответ backend.

### Исключения и альтернативы

`exclusions`: массив `{ "code": "BUSY", "count": 3 }` с кодами:

1. `BUSY`
2. `FORMAT_UNSUPPORTED`
3. `OVER_BUDGET`
4. `LANGUAGE_UNSUPPORTED`
5. `DURATION_EXCEEDED`

При нескольких причинах у профиля сводка учитывает **только первую в этом порядке**. Сумма `count` должна равняться `catalog_count - eligible_count`. Backend может хранить остальные причины внутри, но не должен суммировать пересекающиеся группы в этом ответе.

Альтернатива:

```json
{
  "label": "Бюджет 500 000 ₸",
  "patch": { "budget_kzt": 500000 },
  "match_count": 1
}
```

`match_count` — реальное число после повторного запуска всех строгих фильтров с указанным `patch`. На нажатие frontend применяет patch к **запросу показанного результата** и отправляет новый полный JSON. Неприменённые изменения формы при этом заменяются выбранной альтернативой.

### Проверяемые инварианты

- `MATCHED`: `eligible_count >= 1`, карточек ровно `min(3, eligible_count)`.
- `CATEGORY_ABSENT`: оба счётчика нулевые, карточек нет.
- `NO_MATCH`: `catalog_count > 0`, `eligible_count = 0`, карточек нет.
- ID карточек уникальны; число кандидатов не превышает размер категории.
- Дата доступности, город, категория, формат, цена, язык и применимая длительность не противоречат запросу.
- `request` совпадает с отправленными параметрами. Нельзя молча менять бюджет, дату или город.
- Полный календарь не передаётся в ответе: backend обязан сам исключить занятых кандидатов.
- При одинаковом нормализованном запросе, версиях каталога и ранжирования порядок стабилен.

JSON Schema описывает поля; межполевые инварианты дополнительно проверяются Zod-кодом в `src/domain/selection.ts` и тестами.

## Ошибки и CORS

Ошибки валидации — HTTP 422; технические сбои — HTTP 5xx. Не возвращайте `NO_MATCH` при сбое базы, модели или календаря. Frontend показывает отдельную ошибку, сохраняет условия и предлагает повторить запрос; fallback к локальному каталогу в API-режиме отключён.

Frontend отменяет устаревший запрос через AbortController и ограничивает ожидание десятью секундами. При другом origin разрешите CORS для адреса frontend, методы POST/OPTIONS и заголовок Content-Type. Встроенная авторизация на этой стадии не используется.
